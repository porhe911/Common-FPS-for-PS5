# Common FPS Universal Stage 8 — SELFHOOK + DYNAMIC VIDEOOUT SCAN

Статус: **диагностическая функциональная сборка**, не публичный релиз.

Цель Stage 8 — вернуть реальный счётчик FPS на PS5 с ПО 7.60 и сохранить
работоспособность на 9.60 без прошивочных адресов для записи в чужой процесс.

## Почему Stage 7 не показал FPS

Лог Stage 7 подтвердил сразу две независимые причины:

1. Рендерер действительно был внедрён в SceShellUI и сформировал корректный
   запрос на hook, но межпроцессная операция PT_IO завершилась с кодом
   `EFAULT (14)`. Простое уменьшение записи до 14 байт это не исправляет.
2. Таблица `libSceVideoOut.sprx + 0x34980`, проверенная на ПО 9.60, читается
   на 7.60, но по этому смещению нет активной записи. Значит смещение зависит
   от версии ПО.

Повторять Stage 7 и искать второй ShellUI-лог для этого вывода не требуется.

## Что изменено в Stage 8

- PT_IO больше не используется для установки FPS-hook.
- Внедрённый рендерер компилирует `Application.Update` внутри собственного
  процесса SceShellUI.
- Уже существующий hook etaHEN по-прежнему поддерживается цепочкой.
- Нативный пролог Sony разрешается только после консервативной проверки
  целых x86-64 инструкций. Относительные переходы и RIP-relative инструкции
  отклоняются.
- Первые 16 байт метода заменяются одной атомарной операцией CMPXCHG16B.
  Неизвестный пролог или изменившиеся байты приводят к безопасному отказу без
  частичной записи.
- Память игры только читается через MDBG. Старый direct-map путь разрешён
  исключительно как резервный вариант на проверенной версии ПО 9.60.
- Сначала проверяется известная таблица `+0x34980`. Если она не подходит,
  выполняется ограниченный read-only поиск в данных `libSceVideoOut.sprx`.
- Найденный счётчик принимается только если он стабильно изменяется в двух
  последовательных окнах по 250 мс.
- Перед первым внедрением требуются 10 одинаковых наблюдений PID SceShellUI с
  интервалом одна секунда. Это защищает autoload от слишком раннего запуска.
- Сохранён проверенный жизненный цикл: нет внутреннего `fork`, signal
  handlers, shutdown-записей и возврата внедрённого потока.

## Файлы

- `Common_FPS_PS5_UNIVERSAL_STAGE8_SELFHOOK_SCAN.elf` — отдельная полезная
  нагрузка, в том числе для `autoload.txt`.
- `Common_FPS_PS5_etaHEN_UNIVERSAL_STAGE8_SELFHOOK_SCAN.plugin` — вариант
  для меню плагинов etaHEN.
- `Common_FPS_ShellUI_UNIVERSAL_STAGE8_SELFHOOK_SCAN.elf` — внутренний
  рендерер для диагностики; вручную его запускать не нужно.
- `SHA256SUMS.txt` — контрольные суммы сборки.

ELF и plugin содержат один и тот же контроллер. Одновременно использовать их
нельзя.

## Установка через autoload.txt

Скопируйте основной ELF в каталог autoloader и поставьте его **последней**
строкой:

```text
etaHEN.bin
shadowmountplus.elf
Common_FPS_PS5_UNIVERSAL_STAGE8_SELFHOOK_SCAN.elf
```

Дополнительная задержка в `autoload.txt` не обязательна: сам Stage 8 ждёт
примерно 10 секунд стабильного SceShellUI перед внедрением.

При тесте ELF отключите одноимённый plugin и его автозагрузку в etaHEN.

## Установка как etaHEN plugin

Скопируйте файл `.plugin` в каталог плагинов etaHEN, включите «Запуск» и,
если нужно, «Автозагрузка». Удалите Stage 8 ELF из `autoload.txt`.

На чистой загрузке при выключенной автозагрузке переключатель «Запуск» должен
оставаться выключенным.

## Первый тест

1. Выполните штатную перезагрузку PS5.
2. После прохождения взлома подождите 12–15 секунд на главном экране.
3. Запустите одну игру PS4 и дождитесь появления `FPS: Loading`, затем числа.
4. Закройте игру и запустите одну игру PS5.
5. Закройте игру.
6. Проверьте сначала штатную перезагрузку, затем отдельным запуском — штатное
   выключение.
7. Rest Mode проверяйте последним, когда оба формата игр и питание уже
   отработали стабильно.

При первом подключении к игре динамический поиск может добавить около
0,5–2 секунд к появлению числа FPS.

## Логи

После теста нужны оба файла, даже если один из них короткий:

- `/data/CommonFPS_universal_stage8.log`
- `/data/CommonFPS_universal_stage8_shellui.log`

Успешный hook содержит одну из строк:

```text
Application.Update hook online ... mode=native-selfhook ... atomic16=1
Application.Update hook online ... mode=etahen-chain ... atomic16=1
```

Успешный поиск FPS на неизвестной прошивке содержит:

```text
Sampler read backend ... backend=mdbg
Sampler dynamic chain selected ... offset=... counter=... deltas=...
Sampler online ... first_fps=...
```

Если рендерер не может безопасно обработать пролог, будет строка
`Application.Update native prologue rejected`. В этом случае метод не
изменяется и нужен лог — повторять запуск много раз не следует.

Если поиск не находит подходящий счётчик, будет
`Sampler dynamic scan ... candidates=0` или
`Sampler dynamic validation failed`. Эти строки позволяют расширить поиск
без возврата к опасной межпроцессной записи.

## Критерий готовности к релизу

Stage 8 нельзя сливать в `main` или публиковать как обновление, пока не
подтверждены:

- реальный FPS хотя бы в одной игре PS4 и одной игре PS5 на ПО 7.60;
- сохранение работы версии ПО 9.60;
- две штатные перезагрузки и два штатных выключения;
- отдельная проверка Rest Mode;
- отсутствие CE-108262-9 и «Ошибка системного программного обеспечения».

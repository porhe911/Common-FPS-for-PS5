# Common FPS — Stage 8.3 STOPPED CHAIN HOOK

Статус: **экспериментальная сборка для аппаратной проверки**. Поддержка всех
прошивок не подтверждена. В состав входят основной ELF и plugin с одинаковым
контроллером, а также встроенный рендерер ShellUI.

## Что показал повторный тест 4.51

Основной журнал build 122 содержит:

```text
sdk=0x04510001 backend=mdbg mdbg_rc=0
ShellUI bootstrap ... load=1 ... thread=1 ... imports=59/0
ShellUI changed before marker old_pid=55 new_pid=103 last_stage=hook_setup quarantine=1
```

Это подтверждает вход рендерера и прохождение поиска Mono, загрузки managed
assemblies и получения Game-сцены: отметка `hook_setup` записывается после них.
Затем PID ShellUI изменился, и защита остановила повторные внедрения.
Пользователь в этот момент получил CE-108262-9 и закрытие Astro Bot.

`hook_setup` включает несколько операций: поиск метода, компиляцию, чтение
пролога, подготовку перехода и установку hook. Лог не доказывает, какая из
этих операций вызвала сбой.

При проверке кода обнаружен конкретный риск: для уже установленного etaHEN
перехода старый рендерер напрямую записывал адрес назначения в системный метод.
Доступность этой памяти для записи и безопасный момент изменения на 4.51 не
проверялись. Этот путь убран в Stage 8.3.

## Изменения

1. **Рендерер не записывает системный метод.** И native hook, и цепочка etaHEN
   публикуют запрос контроллеру. Он подключается к ShellUI через ptrace,
   сверяет исходные 16 байт, делает запись и проверяет обратным чтением.
2. Для готового абсолютного перехода меняются только 8 байт адреса назначения.
   Старый обработчик вызывается напрямую по сохранённому адресу; копировать
   его переход в trampoline не требуется.
3. Проверяются формат перехода, адрес назначения, адрес старого обработчика,
   PID, версия протокола, контрольная сумма и сохранность соседних байтов.
4. При ошибке проверки после записи выполняется попытка вернуть исходные
   байты. Неудачу восстановления нельзя считать безопасной — это отражается
   в журнале `restored=0`. Проверка на консоли по-прежнему обязательна.
5. После неудачной установки рендерер не повторяет запись в том же процессе.
   После пропажи ShellUI или тайм-аута готовности контроллер блокирует новые
   внедрения в этой сессии, как в build 122.
6. Стадия `hook_setup` разбита на отдельные отметки. Последняя отметка
   переносится в основной лог, поэтому отсутствие второго лога больше не
   лишает нас всей информации о стадии ошибки.
7. Новые имена файлов и журналов Stage 8.3 исключают путаницу с build 121/122.

Подготовка native trampoline выполняется только в памяти нашего рендерера.
Проверка артефакта требует, чтобы эта область ELF разрешала запись и исполнение.
Импорты `mono_mprotect` и `kernel_mprotect` внутри рендерера запрещены.

## Границы совместимости

| Путь | Текущее поведение |
|---|---|
| ПО 3.00–8.20, включая 4.51 и 7.60 | Запись hook контроллером через MDBG при остановленном ShellUI. Успех самого счётчика этим диапазоном не гарантируется. |
| ПО 9.60, готовый переход etaHEN | Запись контроллером через ptrace I/O; это новый путь, он требует отдельного теста на 9.60. |
| ПО 9.60, нативный пролог | Установка отклоняется. |
| Остальные и неизвестные версии | Запись hook отклоняется до изменения метода. |

Рабочую v1.1.1 на 9.60 пока следует сохранить для обычного использования.
Stage 8.3 не является её стабильной заменой.

## Почему число FPS может всё ещё не появиться

В журнале 4.51 динамический поиск не подтвердил ни одного счётчика: проверки
85–86 кандидатов закончились `Sampler indirect validation failed`.
Отдельный поиск числового FPS в Stage 8.3 не менялся. Он по-прежнему предполагает
поле `root + 0x768`; это расположение ещё не подтверждено для 4.51.

Если после исправления рендера появится только `FPS: Loading`, это подтвердит
работу вывода, но **не получение реального FPS**. Не следует принимать Loading
за успешный результат полного счётчика.

## Один контрольный тест на 4.51

1. Уберите предыдущие Common FPS из autoload и отключите их plugin.
2. Выполните полную штатную перезагрузку и активируйте взлом.
3. Запустите **только основной ELF Stage 8.3 вручную**. Автозагрузку пока не
   включайте: предыдущие тесты сопровождались системной ошибкой.
4. Запустите Astro Bot. Отметьте, появился ли `FPS: Loading`, число FPS или
   системная ошибка. Если игра работает, дайте ей 30 секунд и закройте штатно.
5. При ошибке прекратите тест в этой сессии; повторный запуск поверх старого
   внедрения ничего не прояснит. Сохраните основной журнал.
6. Перезагрузку/выключение проверяйте после успешного запуска и закрытия игры.
   Rest Mode оставьте до подтверждения этих шагов.

## Журналы

- `/data/CommonFPS_universal_stage8_3.log` — основной, обязательный.
- `/data/CommonFPS_universal_stage8_3_shellui.log` — внутренний, если создан.

Вспомогательная отметка `/system_tmp/commonfps_shellui.stage` автоматически
читается контроллером; отдельно копировать её обычно не требуется.

Ожидаемая строка после установки цепочки:

```text
ShellUI hook request ... mode=eta-chain backend=mdbg ... status=0 ... verified=1 ... detached=1 auth_restored=1
ShellUI renderer online ...
```

Значение `status=0` относится к записи hook. Полный FPS подтверждается только
строкой `Sampler online ... first_fps=...` и числом на экране.

| Последняя стадия при сбое | Участок, который нужно проверить |
|---|---|
| `hook_lookup` | Поиск `Application.Update` в Mono |
| `hook_compile` | Получение исполняемого адреса через Mono |
| `hook_read` | Чтение 16 байт пролога метода |
| `hook_prepare` | Проверка типа перехода/пролога |
| `hook_trampoline` | Запись native trampoline в собственную память рендерера |
| `hook_request` | Публикация запроса контроллеру |
| `hook_ack_wait` | Ожидание результата внешней записи |
| `hook_readback` | Проверка установленного перехода в рендерере |
| `hook_confirmed` / `runtime_ready` | Установка hook завершена; следующий шаг — IPC и UI |

Эта отметка указывает последний достигнутый участок, а не точную аварийную
инструкцию. `unavailable` означает отсутствие читаемой отметки соответствующего
PID; сама по себе эта строка не доказывает, что поток не запускался.

## Проверка перед выдачей

Host-тесты проверяют формат/контрольную сумму запроса, отклонение неверного
адреса и изменения соседних байтов, выбор разрешённого пути по прошивке,
сохранение счётчика 9.60 и динамический поиск на макете другой прошивки.
CI собирает контроллер и рендерер, проверяет точное включение рендерера в ELF,
совпадение тела plugin с ELF, RWX-область собственного trampoline и контрольные
суммы. Эти проверки не эмулируют PS5 и не подтверждают совместимость на железе.

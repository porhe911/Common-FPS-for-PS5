# Common FPS Universal Stage 8.2 — STOPPED MDBG HOOK + INDIRECT SCAN

Статус: **диагностическая функциональная сборка**, не публичный релиз.

Stage 8.2 предназначен для проверки реального FPS на ПО 7.60 без возврата к
опасному live self-hook из Stage 8.1. Одновременно сохранён проверенный путь
etaHEN-chain для ПО 9.60.

## Что показал лог Stage 8.1

Контроллер успешно внедрил рендерер:

```text
ShellUI bootstrap ... load=1 ... thread=1 ... imports=60/0
```

После этого online-маркер не появился:

```text
ShellUI marker timeout pid=57
```

Затем PID SceShellUI изменился с `57` на `119`. Это означает, что системный
процесс SceShellUI аварийно завершился и был перезапущен. Именно это совпадает
с окном «Ошибка системного программного обеспечения» и закрытием игры.

Причина локализована: Stage 8.1 менял `Application.Update` из самого
работающего SceShellUI. Атомарная запись 16 байт не останавливает другие потоки,
которые могут в этот момент исполнять изменяемый код.

Второй независимый результат лога относится к FPS:

```text
pointer_matches=3371 indirect_roots=150 candidates=128 truncated=1
```

Очередь заполнилась прямыми ложными указателями раньше, чем до проверки дошли
реальные цепочки с одним разыменованием. Поэтому счётчик также не мог быть
выбран.

## Что изменено

- Полностью удалён native self-hook и импорт `mono_mprotect`.
- Если etaHEN уже поставил свой абсолютный переход, используется
  аппаратно проверенная цепочка v1.1.0: меняется только восьмибайтовый адрес
  назначения.
- На старых версиях ПО с нативным методом рендерер только подготавливает
  trampoline и публикует проверяемый запрос.
- Контроллер делает второй `PT_ATTACH`, останавливает SceShellUI, повторно
  сверяет все 16 исходных байт, пишет переход через `mdbg_copyin`, читает его
  обратно, затем выполняет `PT_DETACH` и восстанавливает исходный Auth ID.
- При несовпадении байт, неподдерживаемой операции или ошибке проверки запись
  отклоняется. После возможной частичной записи выполняется попытка вернуть
  исходные 16 байт до возобновления SceShellUI.
- В память игры ничего не записывается. Игра только читается через MDBG для
  получения VideoOut-счётчика.
- Динамический поиск больше не смешивает прямые ложные указатели с
  аппаратно проверенной цепочкой `record -> pointer -> root -> counter`.
- Быстрый путь по таблице `libSceVideoOut + 0x34980` разрешён только при
  определённом `kern.sdk_version` семейства 9.60. На 7.60, неизвестной версии
  и других версиях ПО используется только проверяемый динамический поиск;
  совпадение байтов по старому адресу больше не принимается за таблицу FPS.
- Лимит независимых косвенных кандидатов увеличен со 128 до 256.
- Сохранены: один resident-контроллер без внутреннего `fork`, десятисекундный
  gate SceShellUI, штатные сигналы, отсутствие shutdown-handler и любых
  записей при выключении/перезагрузке.

## Файлы

- `Common_FPS_PS5_UNIVERSAL_STAGE8_2_STOPPED_MDBG_INDIRECT_SCAN.elf` —
  отдельная нагрузка, в том числе для `autoload.txt`.
- `Common_FPS_PS5_etaHEN_UNIVERSAL_STAGE8_2_STOPPED_MDBG_INDIRECT_SCAN.plugin`
  — тот же контроллер в оболочке etaHEN plugin.
- `Common_FPS_ShellUI_UNIVERSAL_STAGE8_2_STOPPED_MDBG_INDIRECT_SCAN.elf` —
  внутренний рендерер. Вручную его запускать нельзя.
- `SHA256SUMS.txt` — контрольные суммы.

ELF и plugin содержат один и тот же контроллер. Одновременно использовать оба
варианта нельзя.

## Перед тестом

1. Удалите Stage 8.1 и все предыдущие Common FPS из `autoload.txt`.
2. Отключите автозагрузку Common FPS plugin, если проверяется отдельный ELF.
3. Выполните полную штатную перезагрузку. После ошибки Stage 8.1 не запускайте
   Stage 8.2 в той же системной сессии.
4. Убедитесь, что запущен только один Common FPS.

## Установка через autoload.txt

Скопируйте основной ELF в каталог автозагрузчика и поставьте его последней
строкой:

```text
etaHEN.bin
shadowmountplus.elf
Common_FPS_PS5_UNIVERSAL_STAGE8_2_STOPPED_MDBG_INDIRECT_SCAN.elf
```

Сам контроллер ждёт десять последовательных секунд стабильного PID SceShellUI,
поэтому отдельная строка задержки для Common FPS не требуется. Наличие других
нагрузок подряд всё равно может влиять на стабильность самого эксплойта.

## Установка как plugin

Скопируйте `.plugin`, включите «Запуск» и при необходимости «Автозагрузка».
Перед этим удалите отдельный Common FPS ELF из `autoload.txt`.

При выключенной автозагрузке после чистой перезагрузки переключатель «Запуск»
должен оставаться выключенным.

## Первый тест на ПО 7.60

Пока не проверяйте Rest Mode и не запускайте три игры подряд.

1. Выполните чистую перезагрузку и активируйте взлом.
2. Подождите 12–15 секунд на главном экране.
3. Запустите одну игру PS4 или PS5.
4. Подождите до 20 секунд. Сначала может появиться `FPS: Loading`, затем число.
5. Поиграйте две-три минуты и штатно закройте игру.
6. Проверьте одну штатную перезагрузку.
7. Только если счётчик появился и системной ошибки не было, отдельной сессией
   проверьте вторую игру, выключение, а затем Rest Mode.

Если снова появится «Ошибка системного программного обеспечения», не повторяйте
запуск в этой сессии: перезагрузите консоль и сохраните оба лога.

## Логи

Нужны оба файла:

- `/data/CommonFPS_universal_stage8_2.log`
- `/data/CommonFPS_universal_stage8_2_shellui.log`

Для нативного пути на ПО 7.60 ожидается:

```text
ShellUI native hook request ... sdk=0x07600007 ... status=0 ...
expected=1 verified=1 ... detached=1 auth_restored=1
ShellUI renderer online ...
```

В ShellUI-логе:

```text
Application.Update native request ready ...
Application.Update hook online ... mode=native-stopped-mdbg ... verified=1
receiver ready ...
runtime ready ...
```

Успешный поиск счётчика:

```text
Sampler indirect scan ... indirect_roots=... candidates=... truncated=0
Sampler indirect chain selected ... deltas=... estimated_fps=...
Sampler online ... first_fps=...
```

На ПО 9.60 нормальным остаётся:

```text
Application.Update hook online ... mode=etahen-chain ...
Sampler fixed chain selected ...
```

Отрицательный `status` в строке `ShellUI native hook request` означает
безопасный отказ до включения интерфейса FPS. В этом случае важнее прислать
логи, чем повторять запуск.

## Критерий готовности к релизу

Stage 8.2 нельзя сливать в `main` или публиковать как стабильное обновление,
пока не подтверждены:

- реальный FPS хотя бы в одной игре PS4 и одной игре PS5 на ПО 7.60;
- отсутствие системной ошибки и перезапуска SceShellUI;
- сохранение работы на ПО 9.60;
- две штатные перезагрузки и два штатных выключения;
- отдельная успешная проверка Rest Mode.

Одна сборка ELF/plugin может выбирать путь по версии ПО, но это ещё не
означает поддержку **всех** версий: если обновилась структура VideoOut или
SceShellUI, необходимы логи соответствующей прошивки и отдельная проверка
запуска игры, FPS, выключения и перезагрузки. Без успешного теста 7.60
проверенный статус остаётся только у старого пути на 9.60.

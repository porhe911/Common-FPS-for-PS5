# FW 11.60: RC3 ShellUI probe read failure

User report: full RC3 still displays no FPS overlay.

The uploaded `CommonFPS.log` contains 7,048 bytes, 50 lines, SHA-256
`0aa58a89fb9f766aef62bf9c65cffd9fa87fb9c0409484ba8866f65ee572e537`.
Its runtime header identifies v1.2.3 RC3 and SDK `0x11600005`.

## Observed sequence

- The controller finds game PID 99 and ShellUI PID 58.
- Game-module discovery succeeds; game MDBG reads return zero.
- ShellUI bootstrap completes: attach, load, arguments, target stack,
  thread creation and detach succeed. All 67 imports resolve.
- The first code probe at `0x82072b550` uses `ptrace-io`, reports
  `status=-5 read_rc=14 write_rc=-1 expected=0 verified=0`, and detaches
  with authentication restored. No hook write has been attempted.
- The renderer marker then times out at `hook_probe_ack_wait`; the
  injector quarantines that attempt.
- Independently, DCE fixed sampling reaches `first_fps=61` and becomes
  the active sampler. Thus the log confirms sampling without rendering.

The uploaded `CommonFPS_FW1160_Preflight(2).log` is identical to the previous
Preflight fragment, SHA-256
`c621390ba81d75936004ede33aa3f529f091c6eb0568ce98fb15db27492b7dec`.
It does not establish that Preflight ran concurrently with this RC3 test.

## RC4 response and limits

Interpretation: the first demonstrated blocker is PT_IO EFAULT (14)
reading ShellUI code. RC4 tries a checked MDBG read only after that error
on the exact FW 11.60 family. The read is bounded to 16 bytes, accepts
only successful replies with the complete byte count, and verifies
restoration of temporary credentials. Existing hook writes and their
preconditions, verification and rollback are retained.

The MDBG ABI and credential window follow the pinned
[SDK v0.41 `crt/mdbg.c`](https://github.com/ps5-payload-dev/sdk/blob/v0.41/crt/mdbg.c)
and [syscall table](https://github.com/ps5-payload-dev/sdk/blob/v0.41/crt/syscall.h).
The SDK convenience reader returns the syscall result without checking the
final reply status or complete byte count, so it is insufficient for this
hook fallback. Host tests exercise the production checked reader with
simulated successful, short, empty and erroneous kernel replies and
credential setup/restoration failures.

Successful game reads do not prove that MDBG can read this ShellUI address.
RC4 may expose a later write or renderer compatibility failure. Console
overlay operation remains unconfirmed until a new hardware test. The
separate shutdown reproduced without Common FPS is not attributed to it.

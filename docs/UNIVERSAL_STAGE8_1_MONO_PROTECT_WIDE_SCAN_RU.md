# Common FPS Universal Stage 8.1 — MONO PROTECT + WIDE VIDEOOUT SCAN

Статус: **диагностическая функциональная сборка**, не публичный релиз.

Цель Stage 8.1 — исправить доказанный сбой загрузки рендерера на ПО 7.60,
вернуть оверлей в SceShellUI и продолжить безопасный поиск реального FPS без
записи в память игры. Проверенный быстрый путь для ПО 9.60 сохранён.

## Что показали два лога Stage 8

Оба предоставленных лога относятся к успешно запущенному основному ELF:

```text
Worker ready pid=... ppid=86
Sampler read backend ... sdk=0x07600007 backend=mdbg mdbg_rc=0
```

Значит контроллер работал, находил игры и читал их память через MDBG.
Отсутствие записи в списке «активных нагрузок» само по себе не означает, что
ELF не запущен: файл стартует через внешний ps5_autoloader, а не регистрируется
как активный plugin в интерфейсе etaHEN.

Второй лог не создавался по точной причине:

```text
ShellUI bootstrap ... load=0 ... imports=36/1 first=kernel_mprotect
```

Внедряемый ShellUI ELF не мог разрешить `kernel_mprotect`, поэтому его
`elf_main` ни разу не выполнялся. Следовательно файл
`CommonFPS_universal_stage8_shellui.log` физически не мог появиться.

Отдельно подтверждено, что чтение на 7.60 работает, но старый динамический
поиск был слишком узким:

```text
Sampler fixed table ... sdk=0x07600007 enabled=0
Sampler dynamic scan ... candidates=0
```

## Что изменено в Stage 8.1

- Удалён импорт `kernel_mprotect` из ShellUI ELF.
- Защита страниц собственного процесса SceShellUI переключается через уже
  загруженный экспорт Mono `mono_mprotect`.
- Проверка сборки запрещает появление `kernel_mprotect` и требует наличие
  `mono_mprotect`.
- Read-only диапазон поиска VideoOut расширен с
  `+0x18000…+0x70000` до `+0x10000…+0x200000`.
- Проверяются четыре консервативных варианта расположения флага и указателя:
  `e0-p8`, `e4-p8`, `e0-p10`, `e4-p10`.
- Для каждого варианта проверяются как проверенная двойная цепочка указателей,
  так и прямой указатель старых структур.
- Адрес принимается только после двух независимых 250-мс измерений с
  правдоподобной частотой и малым разбросом.
- После неудачного полного поиска действует пауза 10 секунд, чтобы autoload не
  сканировал память игры каждую секунду.
- Память игры остаётся строго read-only. Запись выполняется только рендерером
  внутри собственного процесса SceShellUI и только одной атомарной
  16-байтовой операцией после проверки пролога.
- Сохранён проверенный жизненный цикл: нет внутреннего `fork`, обработчиков
  сигналов, shutdown-записей и возврата внедрённого потока.

## Файлы сборки

- `Common_FPS_PS5_UNIVERSAL_STAGE8_1_MONO_PROTECT_WIDE_SCAN.elf` — основной
  ELF для ручного запуска или `autoload.txt`.
- `Common_FPS_PS5_etaHEN_UNIVERSAL_STAGE8_1_MONO_PROTECT_WIDE_SCAN.plugin` —
  тот же контроллер в оболочке etaHEN plugin.
- `Common_FPS_ShellUI_UNIVERSAL_STAGE8_1_MONO_PROTECT_WIDE_SCAN.elf` —
  встроенный диагностический рендерер. **Не добавлять в autoload и не
  запускать вручную.**
- `SHA256SUMS.txt` — контрольные суммы всех трёх файлов.

Одновременно использовать основной ELF и plugin нельзя.

## Правильный autoload

Сначала удалите из `autoload.txt` все предыдущие Common FPS ELF. Основной
Stage 8.1 должен быть единственной строкой Common FPS и стоять последним:

```text
etaHEN.bin
shadowmountplus.elf
Common_FPS_PS5_UNIVERSAL_STAGE8_1_MONO_PROTECT_WIDE_SCAN.elf
```

Встроенная защита сама ждёт 10 одинаковых наблюдений PID SceShellUI с
интервалом одна секунда. Специальная задержка в `autoload.txt` не требуется.

На время теста ELF отключите автозагрузку Common FPS plugin в etaHEN. Если
тестируется plugin, наоборот удалите основной ELF из `autoload.txt`.

## Перед тестом

Удалите старые диагностические файлы, чтобы не смешать результаты:

```text
/data/CommonFPS_universal_stage8_1.log
/data/CommonFPS_universal_stage8_1_shellui.log
```

Старые Stage 8 логи можно сохранить отдельно; Stage 8.1 использует новые
имена и не дописывает в них.

## Первый функциональный тест на ПО 7.60

1. Установите только основной Stage 8.1 ELF последней строкой autoload.
2. Выполните штатную перезагрузку и пройдите взлом.
3. Игру можно запустить сразу. Из-за внутреннего 10-секундного gate оверлей
   может появиться уже после запуска игры.
4. Оставьте одну игру PS4 в реальном игровом процессе не менее 30 секунд.
5. Закройте её, затем запустите одну игру PS5 и также подождите 30 секунд.
6. Закройте игру и сначала проверьте штатную перезагрузку.
7. Отдельным чистым запуском проверьте штатное выключение.
8. Rest Mode тестируйте только после успешных игр, перезагрузки и выключения.

Первое число FPS может появиться позже самого оверлея: широкий поиск выполняет
read-only проверку кандидатов и при необходимости повторяется через 10 секунд.

## Какие строки означают успех

В основном логе:

```text
ShellUI bootstrap ... load=1 ... imports=37/0 first=none
ShellUI renderer online ...
Sampler wide scan ...
Sampler wide chain selected ... counter=... deltas=...
Sampler online ... first_fps=...
```

Во втором логе:

```text
Common FPS Universal Stage 8.1 Mono-protect wide VideoOut scan
Application.Update hook online ... mode=native-selfhook ... atomic16=1
```

Режим `mode=etahen-chain` также допустим, если etaHEN уже установил свой
совместимый hook.

## Если FPS не появился

Нужны оба новых файла:

- `/data/CommonFPS_universal_stage8_1.log`
- `/data/CommonFPS_universal_stage8_1_shellui.log`

Если второго файла снова нет, достаточно первого: строка
`ShellUI bootstrap` теперь покажет точный импорт или этап загрузки.

Строки `Sampler wide candidate` содержат первые значения и дельты
обнаруженных адресов. По ним можно изменить именно распознавание структуры
7.60, не возвращаясь к опасным прошивочным адресам для записи.

Если появляется системная ошибка CE-108262-9, игра закрывается или питание
ведёт себя нештатно, прекратите повторные запуски этой сборки и сохраните оба
лога. Одного воспроизведения достаточно.

## Критерий готовности к GitHub-релизу

Stage 8.1 остаётся в тестовой ветке и не сливается в `main`, пока не
подтверждены:

- реальное целое значение FPS в игре PS4 и игре PS5 на ПО 7.60;
- отсутствие регрессии на ПО 9.60;
- две штатные перезагрузки и два штатных выключения;
- отдельный успешный цикл Rest Mode;
- отсутствие CE-108262-9 и ошибок системного программного обеспечения.
